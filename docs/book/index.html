Chapter 1

From empty repository to runnable service

Before an API can move money it has to start, connect to its database, and answer a request. This chapter follows that path and shows why a running service is not the same as a working payments product.

You will be able to
  • describe what happens between java -jar and the first HTTP response;
  • explain what a is and why it needs a version;
  • tell a Dockerfile from a Compose file, and a from a single-stage one;
  • explain why the API openly reports that payments are disabled.

Mental model

An HTTP API is a long-running process that listens on a port, maps each request to a method, and writes a response. Spring Boot assembles that process for you: it scans your code for components, wires them together with , and starts an embedded Tomcat web server.

Around that process sit three tools you will use in every chapter:

  • Docker packages the application with its Java runtime into an image, so it runs the same everywhere.
  • Docker Compose starts that image next to PostgreSQL, wires up the network and environment variables, and waits until the database is healthy.
  • keeps the database schema under version control, so every environment has the same tables.

      Exercises
      
      
      What does curl -X POST http://localhost:8080/api/v1/payments return?
      404 Not Found with a problem body: "detail":"No static resource api/v1/payments.". Nothing maps that path yet. Compare with POST /api/v1/payments/capabilities, which returns 405 because that path exists for GET.
      
      
      Explain the difference between the Dockerfile and compose.yaml
      The Dockerfile describes how to build one image. compose.yaml describes how to run several containers together: which images, which environment variables, which ports, and in what order (the API waits for PostgreSQL's health check).
      
      
      Which file controls the database schema?
      The SQL files in apps/payment-api/src/main/resources/db/migration/, applied by Flyway. Not Hibernate: ddl-auto: validate only checks.
      
      
      Add a safe field to the capabilities response
      Add for example "currency", "USD" to the Map.of(...). The existing CapabilitiesControllerTest still passes, because it checks specific fields, not the whole body. Add an assertion for your new field, run mvn verify, and update this book's code excerpt. The CI snippet check fails if you forget.

        • 
          
        •

      Smaller images download faster and give an attacker fewer tools. The dependency cache layer is what speeds up builds, not the second stage.

      Chapter 2
      
      
      Accounts, and a balance that cannot lie
      
      
      You can now open an account and read its balance. The balance is always zero, and nothing in the system can change it. That restriction is the main lesson of this chapter.
      
      
      
        You will be able to
        
        
          
      • explain why a balance should be derived from records, not stored as an editable number;
        • 
          
      • represent money without floating point;
        • 
          
      • trace a request through controller, service, domain, repository and database, and say which layer owns which rule;
        • 
          
      • write migration constraints that hold even when application code is bypassed;
        • 
          
      • say what unit, contract and integration tests can and cannot prove.
        • 
        
      
      
      

      
      Mental model: the statement is the truth
      
      
      A bank statement is a list of entries with a total at the bottom. If the total and the entries ever disagree, the entries win. In accounting terms, the  is a : computed from , never typed in.
      
      
      This chapter adopts that rule before any postings exist. The account table has no balance column, no endpoint accepts an amount, and every balance is computed as zero. That is the strongest possible form of “transfers never create funds”: there is no code that could.

      Money is an integer
      
      
      Most decimal fractions have no exact binary representation. A double stores the closest value it can, and the small errors pile up with every addition. The project stores money as an integer count of the currency's : $12.34 is 1234 cents. Try it below. JavaScript numbers use the same IEEE 754 format as Java's double, so the left side shows exactly what Java would compute.

        Failure lab: the microsecond bug
        
      
        While building this chapter, the integration test failed with two timestamps that looked identical at a glance:
        
      
        expected: AccountResponse[..., createdAt=2026-10-29T04:22:46.720618319Z]
 but was: AccountResponse[..., createdAt=2026-10-29T04:22:46.720618Z]
        
      
        The POST response echoed the in-memory timestamp with nine fractional digits. PostgreSQL kept six. A client that compared the two, or used createdAt as a paging cursor, would see the record change between writing and reading it.

        Exercises
        
      
        POST {"displayName":"Bob","currency":"usd"}. What status comes back?
        400. The pattern is case-sensitive. Should the API accept lowercase? If so, decide where to normalize it (DTO, controller or domain) and write down why.
        
      
        In psql, run INSERT INTO account VALUES (gen_random_uuid(), 'Mallory', 'EUR', now());
        ERROR: new row for relation "account" violates check constraint "account_currency_check". The API's @Pattern can't help here because psql never touches the API. Open psql with docker compose exec postgres psql -U p2p_lab -d p2p_lab.
        
      
        Change @Column(name = "display_name") to "name" in AccountEntity and run mvn verify. Which tests fail?
        Only AccountPersistenceIntegrationTest. Its Spring context fails to start with Schema-validation: missing column [name] in table [account]. AccountControllerTest still passes because it never loads JPA. Revert afterwards.
        
      
        Add a comment line to V2__accounts.sql and restart the Compose stack. What happens?
        Startup fails with a Flyway checksum mismatch for version 2. Flyway refuses to run against a database whose history disagrees with the files. Revert. To change the schema, add V3__….sql.
        
      
        POST the same body twice. How many accounts exist?
        Two, with different ids. Write down how a mobile client could end up sending a request twice: a timeout, a retry button, a flaky network. Keep the note for Chapter 4.
        
      
        Run docker compose logs payment-api | grep "account opened". What appears?
        The account id and currency. The display name never appears in logs.
        
      
        Exercise 7: close the tab gap
        In the defense-in-depth playground, a name made only of a tab gets into the table through SQL. PostgreSQL confirms it: INSERT INTO account VALUES (gen_random_uuid(), E'\t', 'USD', now()); succeeds.
        Write V3__account_display_name_not_whitespace.sql that replaces the constraint with one that rejects any all-whitespace name. Hint: drop account_display_name_check, then add a check using a regular expression such as display_name ~ '\S'. Add an integration test that inserts E'\t' and expects DataIntegrityViolationException. Think about what happens if an existing row already violates the new rule.

        In Java, what does 0.1 + 0.2 == 0.3 evaluate to, and why?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        IEEE 754 doubles store the nearest binary fraction. The tiny error is invisible in one addition and real after a million. Integer cents never round.
        
      
        
      
        
        
        How is $12.34 represented in this project's API?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        Integer minor units (cents), in fields named …Minor. A JSON client never has to parse money as a floating-point number.
        
      
        
      
        
        
        Why does the account table have no balance column?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        The balance is a read model derived from postings. If a stored balance is ever needed for speed, it must change in the same transaction as the postings and be checkable against them. That would need its own ADR.
        
      
        
      
        
        
        A POST arrives with "currency": "EUR". Which code runs?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        @Valid fails before the method is called, so no transaction ever begins. The cheapest rejection is the earliest one.
        
      
        
      
        
        
        Someone runs an INSERT with currency 'EUR' directly in psql. What stops it?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        psql bypasses every Java layer. Only rules in the schema protect the table from code you don't control, such as scripts, batch jobs and future services.
        
      
        
      
        
        
        An unknown id returns 404. What does GET /api/v1/accounts/not-a-uuid return?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        A malformed id is a bad request, not a missing resource. The conversion fails during argument binding, so the service never runs.
        
      
        
      
        
        
        Why did only the integration test catch the microsecond bug?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        Each test level can only find bugs in what it actually runs. Precision loss happens at the database boundary, so only a test that crosses that boundary can see it.
        
      
        
      
        
        
        A mobile app's POST times out, and the app retries. What happens today?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        Nothing links the two requests yet, and names aren't unique. For accounts that's a nuisance; for payments it would be a double charge. That is why Chapter 4 adds idempotency keys.
        
      
        
      
        
        
        Why does GET /api/v1/accounts return 405 instead of 404?
        
        
          
          
          • 
          
          • 
          
          • 
          
          • 
        
        
        
        The Allow: POST header says so. There is deliberately no list endpoint: without authentication it would show every account to anyone.

          • 
          
          • 
          
          • 
          
          •

        Reference
        
      
        Glossary
        
      
        Every underlined term in the book links here. Definitions describe how this project uses the word.
        
      
        
        
        Available balance
        
        
        What can be spent right now: the ledger balance minus holds, which are funds reserved for payments still in flight. Holds arrive with payments in Chapter 4.
        
        
        Bean Validation
        
        
        The Jakarta standard for declaring input rules with annotations such as @NotBlank and @Size. Spring checks them when a parameter is marked @Valid.
        
        
        Contract test
        
        
        A test of an interface's promises (status codes, field names, validation) with the code behind it replaced by a mock. Fast, but blind to the real implementation.
        
        
        Dependency injection
        
        
        Classes receive their collaborators through the constructor instead of creating them. Spring builds the objects and passes them in, which makes swapping a fake in tests easy.
        
        
        Flyway
        
        
        A tool that applies versioned SQL migration files in order and records each one in the flyway_schema_history table.
        
        
        Idempotency
        
        
        The property that doing something twice has the same effect as doing it once. Payment APIs achieve it with a client-supplied key, so a retried request returns the original result instead of paying twice.
        
        
        Ledger balance
        
        
        The sum of all postings to an account. Computed, never typed in.
        
        
        Migration
        
        
        A versioned SQL script that changes the database schema. Once applied, it is never edited; the next change is a new, higher version.
        
        
        Minor unit
        
        
        The smallest unit of a currency. For USD it is the cent, so $12.34 is 1234 minor units.
        
        
        Multi-stage build
        
        
        A Dockerfile with several FROM lines. Early stages build; the final stage copies only the result, leaving compilers and source code behind.
        
        
        Port and adapter
        
        
        A port is an interface the core of the application defines, such as AccountRepository. An adapter implements it with a specific technology, such as JpaAccountRepository with JPA.
        
        
        Posting
        
        
        An immutable ledger record that moves an amount between accounts. Every movement debits one account and credits another by the same amount. Introduced in Chapter 3.
        
        
        Problem Detail
        
        
        The standard JSON error format from RFC 9457, with type, title, status, detail and instance fields, served as application/problem+json.
        
        
        Read model
        
        
        Data computed for display from authoritative records, rather than being authoritative itself.
        
        
        Testcontainers
        
        
        A library that starts real dependencies, such as PostgreSQL, in throwaway Docker containers for the length of a test run.
        
        
        Transaction
        
        
        A unit of database work that either fully commits or fully rolls back. Partial results are never visible.
